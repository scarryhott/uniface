## One deterministic project boundary

`closure_supernet/deterministic_project_closure.py` inventories every tracked
project artifact in lexical path order and hashes its exact bytes. Each artifact
receives exactly one project role:

- authoritative transition;
- transport or projection;
- retained runtime or natural form;
- formal proof;
- verification;
- deterministic enforcement;
- deployment infrastructure;
- documentation or other project artifact.

The resulting manifest is content addressed. It has no clock, process, random,
absolute-path, or file-system enumeration input.

The manifest does not make all files semantically authoritative. It makes the
status of every file explicit while preserving the single authority boundary.
Historical managers and natural-form implementations remain available as
versioned project evidence, but a deterministic import-closure audit prevents
legacy agent mutation calls from becoming reachable from the published
entrypoint.

## Blocking enforcement

The CI order is now:

1. install the project;
2. execute `closure-supernet-project-audit --root .`;
3. run the current closure test lane;
4. run the historical compatibility lane;
5. verify the one published closure surface.

A change cannot pass the current lane when it:

- installs a second `supernet_translate` owner;
- makes a historical agent mutation reachable from the public entrypoint;
- adds another reachable mutating HTTP authority;
- disconnects the agent from `app.state.supernet_translate`;
- gives self-runtime a mutating route or truth authority;
- removes the deterministic project closure from the public entrypoint;
- leaves a tracked project artifact unclassified;
- makes identical exact runtime inputs produce different semantic identities.
